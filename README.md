# 議事録作成ツール

会社ごとの議事録テンプレートに合わせて、**音声・文字起こし・メモ**から議事録を自動作成するWebアプリです。
利用者がAIに指示（プロンプト）を書く必要はなく、画面の項目を埋めてボタンを押すだけで使えます。

- サーバー不要（GitHub Pages で公開できる静的サイト）
- 入力内容・作成結果は**どこにも保存しない**設計
- AI は Google Gemini API（有料プラン）を使用

---

## 主な機能

| 項目 | 内容 |
|---|---|
| テンプレート | Word（.docx）／Excel（.xlsx）／PDF／テキストを読み込み、見出し・表・項目順を再現。未指定時は標準形式 |
| 会議情報・参加者 | 会議名・日時・場所・記録者、参加者（最大10名、任意）、社内用語の表記 |
| 議事録のもと | 音声ファイル／その場で録音／文字起こし（Teams・Zoom の .vtt・.docx 対応）／メモ。組み合わせ可 |
| 発言者の特定 | 音声は話者A・B…で聞き分けて文字起こし → 名前の呼びかけ・自己紹介・役割・所属の話題から各話者が誰かを推定し、根拠と確度を表示 → 利用者が確認・修正してから議事録に反映（不明な話者は推測で名前を当てず「話者A」と記載） |
| 精度を上げる仕組み | ①音声は先に忠実に文字起こし → ②議事録作成 → ③別担当として元の記録と照合し、根拠のない記述・漏れ・誤りを修正（「精度優先」ON 時） |
| 確認支援 | 記録から判断できない箇所を本文に【要確認】で表示し、一覧でも提示 |
| 出力 | 画面上で直接修正 → Word（.docx）／PDF（印刷）／テキスト／コピー（Word・メールに罫線ごと貼り付け可） |

## 情報の取り扱い（情報流出防止の設計）

- **保存しない**：入力・テンプレート・音声・作成結果はブラウザのメモリ上だけで扱い、ブラウザの保存領域（localStorage 等）にも書き込みません。画面を閉じる・再読み込みで消えます（閉じる前に確認メッセージを表示）。
- **通信先を限定**：`index.html` のセキュリティ設定（CSP）で、通信先を自サイトと Gemini API（と中継サーバー）だけに制限しています。外部フォント・解析ツール・CDN は使っていません（ライブラリは `vendor/` に同梱）。
- **音声の即時削除**：音声は処理のため一時的に Google にアップロードされますが、文字起こしが終わるとすぐ削除命令を送ります。
- **AIの学習に使われない条件**：Gemini API は **有料（課金を有効にした）プロジェクト** であれば、送信内容を学習に使いません。**無料枠の API キーでは学習に利用される可能性があるため、業務では必ず課金を有効にしたプロジェクトのキーを使ってください。**
- 保持されるのは、利用者が選んだ場合の「接続キー」と「モデルの選択」だけです。

## 公開手順（GitHub Pages）

1. このフォルダの中身をそのまま GitHub リポジトリにアップロード
2. リポジトリの **Settings → Pages** で「Deploy from a branch」→ `main` / `(root)` を選んで保存
3. 数分後に表示される URL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）を社内に共有

> 公開リポジトリのファイルは誰でも見られます。**API キーをファイルに書かないでください。**

## 接続キーの準備（どちらか一方）

### 方法A：利用者がキーを登録する（手軽）
1. 管理者が [Google AI Studio](https://aistudio.google.com/) で API キーを作成し、**課金を有効化**
2. 利用者は画面右上「設定」→ キーを貼り付け →「接続テスト」→「保存」
   - 既定では画面を閉じるまでのみ保持。「このパソコンに記憶」を選ぶと次回から入力不要

### 方法B：中継サーバーを使う（利用者はキー不要・推奨）
キーを利用者に配らずに済みます。Cloudflare Workers（無料枠あり）を使います。
1. Cloudflare で Worker を作成し、`proxy/cloudflare-worker.js` の内容を貼り付けてデプロイ
2. Worker の設定で変数を登録
   - `GEMINI_API_KEY`（シークレット）：API キー
   - `ALLOWED_ORIGIN`：`https://<ユーザー名>.github.io`
   - `ACCESS_CODES`（シークレット）：利用コード。`名前:コード` をカンマ区切りで並べると、人ごとに発行・停止できる（例：`sato:K7m2Qx9P,suzuki:R4t8Wn2L`）
3. `config.js` の `PROXY_URL` に Worker の URL を設定
4. 利用者には、アプリの URL と本人用の利用コードを伝える（利用者は「設定」に利用コードを入れるだけ）
5. `*.workers.dev` 以外のドメインにした場合は `index.html` の `connect-src` に追記

※ Cloudflare 無料プランは1回の送信が 100MB までです。それ以上の音声は方法Aを使うか、圧縮してください。

## 管理者向け設定（`config.js`）

| 設定 | 説明 |
|---|---|
| `APP_NAME` | 画面に表示するツール名 |
| `PROXY_URL` | 中継サーバーの URL（方法B） |
| `MODEL` | モデルを固定する場合に指定。空欄なら利用可能な最新の安定版を自動選択 |
| `MODEL_PREFERENCE` | 自動選択時の優先：`"pro"`（精度）／`"flash"`（速度・費用） |
| `PRESET_TEMPLATES` | `templates/` に置いたテンプレートをプルダウンで選べるようにする |

## ファイル構成

```
index.html            画面
config.js             管理者向け設定
css/style.css         デザイン
js/app.js             画面の動作
js/prompts.js         AIへの指示文（議事録の品質はここで調整）
js/gemini.js          Gemini API との通信
js/files.js           テンプレート・文字起こしファイルの読み込み
js/exporter.js        Word・テキスト出力、コピー
vendor/               同梱ライブラリ（mammoth, SheetJS, docx）
proxy/                中継サーバーのサンプル
templates/            登録済みテンプレートの置き場所（任意）
```

## 発言者を正確に記録するコツ

- 会議の冒頭で、一人ずつ名前を名乗ってもらう
- 発言を求めるときは「〇〇さん、いかがですか」と名前で呼ぶ
- 参加者欄に所属・役職・役割（司会など）も入れておく

## 動作環境・制限

- 推奨ブラウザ：Google Chrome／Microsoft Edge（最新版）。録音は https で公開した場合のみ動作します
- 古い Word 形式（.doc）は読み込めません。.docx で保存し直してください
- Word 出力は議事録の内容と構成（見出し・表・箇条書き）を再現しますが、元テンプレートのロゴ・ヘッダー・フォント等の装飾までは引き継ぎません。体裁を完全に合わせたい場合は「コピー」して元のテンプレートに貼り付けてください
- 自動作成のため誤りが含まれる場合があります。配布前に必ず内容を確認してください
